# 📦 Fulfillment Hub

A simple, operational tool that helps an e-commerce business (XYZ) manage its order fulfillment process — built as a take-home assignment.

**🔗 Live app:** https://fulfillment-xyz.streamlit.app/

## The problem

XYZ currently runs fulfillment using spreadsheets and shared folders. As order volume has grown, this has become hard to manage:
- It's difficult to see order status at a glance
- Delays go unnoticed
- Priority orders get mixed in with regular ones and miss deadlines
- Stock information is unreliable, so orders get blocked without anyone noticing why
- Courier pickups are sometimes missed

## What this app does

Rather than building a static reporting dashboard, this is a working operational tool — a warehouse or office team member can search for orders, see exactly where each one is in the fulfillment pipeline, understand why an order is stuck, and move it forward.

**Pages:**
- **Home** — quick summary and navigation
- **Dashboard** — today's KPIs and an "Attention Required" section surfacing urgent issues
- **Orders** — a searchable, filterable table of all orders, sorted so priority/delayed orders surface first
- **Order Details** — select any order to see its full journey (Order Received → Processing → Picking → Packing → Staging → Shipped), shipping/staging info, and update its status
- **Inventory** — stock levels across the main and overflow warehouses, with low/out-of-stock flags and a live list of exactly which orders are blocked and why

## Why I focused on these problems

I chose to go deepest on two problems: **priority/delay visibility** and **inventory-driven blocking**, since these are the most measurable, data-driven causes of missed deadlines and stalled orders. I also modeled a detail from the brief that's easy to miss — stock is split across a main and an overflow warehouse, and an order can be "blocked" even though stock technically exists, because it hasn't been physically moved to the picking warehouse yet.

I did not build dedicated features for wrong-item-shipped or misplaced-box tracking, since solving those properly would need a barcode/scan-verification step that felt out of scope for this timeline. I did add a lightweight reminder at the Picking stage prompting a double-check of the product/variant before packing, as a small step toward that problem without overbuilding it.

## Tech stack

- **Python** + **Streamlit** (UI/app framework)
- **Pandas** (data handling)
- **CSV files** as the data layer (synthetic, generated by `generate_data.py`)

I chose Streamlit because it lets me build a genuinely interactive internal tool quickly, without introducing unnecessary complexity (no database, no backend API, no JavaScript framework) that wouldn't add real value for a take-home of this scope.

## Data

All data is synthetic, generated by `generate_data.py`, and internally consistent — for example, an order is only marked "blocked by inventory" if its SKU actually has zero available stock in the main warehouse, and shipping/staging records only exist for orders that have reached that stage.

- `products.csv` — product catalog (11 products)
- `inventory.csv` — stock per product per warehouse (main + overflow)
- `orders.csv` — all orders, with computed status flags
- `shipping.csv` — staging/pickup info for orders that reached the Staging/Shipped stage

## Running it locally

```bash
git clone https://github.com/aprajitad/-fulfillment-hub.git
cd -fulfillment-hub
pip install -r requirements.txt
python generate_data.py
streamlit run Home.py
```

The app will open automatically in your browser at `http://localhost:8501`.

## Note on the deployed version

Since this app uses CSV files rather than a real database, status updates made on the **live deployed version** apply only within that session and may reset if the app restarts. A production version of this tool would connect to a real database so changes persist permanently.
